# 知枢阶段 9.2：State Steward 生产适配与前端审阅说明 v1.0

> 当前状态：阶段 9.2 `COMPLETED`；阶段 9 `COMPLETED`。  
> 边界：阶段 10 Multi-Agent / Worktree / Integration Gate 未启动。

## 1. 信任边界

浏览器只提交 `reportId`。候选标题、正文、类型、Evidence Reference 和候选处置都由 Project Control 基于不可变 Execution Report / Artifact 快照生成。

```text
PASSED Execution Report
  -> StructuredExecutionReportV1
  -> State Steward candidate analysis
  -> STATE_CHANGE Proposal
  -> user confirm / reject
  -> NEW only State update / audited rejection
```

报告没有 `PASSED` Human Verification 时拒绝提取。State Steward 仍无 State、Fact、Decision、Plan、文件系统、Shell 或 Git 写权限。

## 2. 生产适配规则

- 显式 `artifact.metadata.stateCandidates` 只接受 `DISCOVERY / DECISION / CONSTRAINT / RISK`。
- `FACT` 和不完整候选被拒绝；显式非法候选不会借 fallback 转换成其他类型。
- 没有显式候选时，SUMMARY 形成低权威 Discovery，ERROR_REPORT 形成低权威 Risk。
- 每个真正产出候选的 Artifact 自动创建或重用 `STATE_STEWARD_CANDIDATE` Evidence Reference。
- 同一报告重放返回 V17 唯一约束下的原 Proposal，不会重复制造待审阅项。

## 3. API

浏览器同源 Gateway：

```text
GET  /api/task-center/projects/:projectId/state/proposals
POST /api/task-center/projects/:projectId/state/steward/reports/:reportId/proposal
POST /api/task-center/projects/:projectId/state/proposals/:proposalId/confirm
POST /api/task-center/projects/:projectId/state/proposals/:proposalId/reject
```

Project Control `1.6.0`：

```text
GET  /internal/project-control/v1/projects/{projectId}/state/proposals
POST /internal/project-control/v1/projects/{projectId}/state/steward/reports/{reportId}/proposal
```

9.1 的内部 Structured Report 端点暂时保留兼容，但已标记 deprecated，浏览器不再暴露该入口。

## 4. 审阅面

- PASSED Execution Report 可发起“提取 State 候选”。
- Project State 面板按 Proposal 展示 `NEW / STALE / CONFLICT`、类型、正文、理由、证据数量和合并数量。
- 确认是提案级命令，Control Plane 只应用 `NEW`；候选文本不能在浏览器改写。
- 拒绝必须填写原因；历史保留创建与决策 actor、时间、状态和 Applied Revision。
- 已确认 Discovery 与 Risk 会在 Project State 的“发现与风险”区域显示。
