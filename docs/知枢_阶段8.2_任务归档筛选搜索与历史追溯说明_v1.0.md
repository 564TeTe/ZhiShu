# 知枢阶段 8.2：任务归档、筛选、搜索与历史追溯说明 v1.0

> 当前状态：阶段 8.2 已完成并通过本批次验收；阶段 8、G8 尚未完成。  
> 批次结论：阶段 8.2 收口时默认入口尚未切换；当前状态见阶段 8.4 说明。

## 1. 批次目标

让新 Task Center 可以在长期项目中稳定浏览活动任务与归档任务，不再依赖固定数量的“最近任务”快照。读取必须有项目归属边界、稳定分页游标和可追溯的历史详情。

本批次覆盖：

- 活动、归档、全部三种任务范围；
- Attempt 状态和业务验收状态筛选；
- 标题、目标和 Task ID 搜索；
- 基于 `createdAt + taskId` 的稳定 keyset 分页；
- 终态 Task 的 Archive 操作；
- 归档后 Task、Attempt、Artifact、Approval 和 Follow-up 历史读取。

本批次不覆盖项目级订阅、断线补放、性能指标或默认入口切换。

## 2. Archive 语义

Archive 复用 V8 的 `agent_task.archived_at`、`archived_by` 和 `archive_reason` 字段，不删除任何 Task、Attempt、Runtime Event、Artifact、Approval、Acceptance 或 Follow-up 数据。

只有当前 Attempt 为 `SUCCEEDED`、`FAILED`、`LOST` 或 `ABORTED` 时允许 Archive。重复 Archive 请求返回已归档快照；活动 Task、归档 Task 的历史详情都不能通过新入口恢复执行命令。

归档任务仍可通过项目级历史端点读取详情和 Attempt 历史。Gateway 在转发 Archive 前重新解析稳定 Control Project，并从认证会话生成 `user:<id>` actor；浏览器不能自报 actor 或跨项目猜测 Task ID。

## 3. 查询契约

Control Plane 新增项目级端点：

- `GET /internal/project-control/v1/projects/{projectId}/tasks`
- `GET /internal/project-control/v1/projects/{projectId}/tasks/{taskId}`
- `GET /internal/project-control/v1/projects/{projectId}/tasks/{taskId}/attempts`
- `POST /internal/project-control/v1/tasks/{taskId}/archive`

历史列表默认只读活动任务，单页最多 100 条。游标由服务端生成并校验，排序固定为 `created_at DESC, id DESC`，避免相同时间戳导致重复或漏项。搜索模式限制为 200 个字符，Gateway 对范围、状态、游标和页大小做传输层校验。
