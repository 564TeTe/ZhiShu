## 1. 项目活动语义

V16 新增 `project_activity_event`，以稳定 Control Project ID 和单调 `BIGSERIAL` 游标组织项目变化。活动记录覆盖 Task、Attempt、Approval、Artifact、Acceptance、Follow-up、Project State、Brain、Plan 和 Work Order 的关键状态变化。

活动事件只表达“哪些事实可能变化”，不复制 Artifact 内容、模型输出或原始 Runtime payload。前端收到事件后重新读取权威接口，不在浏览器中重建第二套状态机。

Control Plane 端点：

- `GET /internal/project-control/v1/projects/{projectId}/activity`
- `GET /internal/project-control/v1/projects/{projectId}/metrics`

Gateway 端点：

- `GET /api/task-center/projects/{projectId}/activity`
- `GET /api/task-center/projects/{projectId}/metrics`

## 2. 游标与断线恢复

- 首次不带 `after` 读取只返回当前 head，不重放历史；客户端先记录 head，再执行一次完整权威刷新。
- 后续请求携带最后成功处理的 `after`，服务端按 cursor 递增返回最多 200 条事件。
- 投递语义为 at-least-once；前端以 `eventId` 做有限去重，只在刷新触发成功后推进 cursor。
- 默认逻辑重放窗口为每项目最近 10,000 条事件。旧游标低于 `retentionFloorCursor` 时返回 `RESYNC_REQUIRED`，客户端记录新 head 后执行全量刷新。
- 正常增量间隔为 3 秒；连接失败后保留 cursor，每 15 秒重试。连续失败时界面显示轮询兜底，原有 10～15 秒权威读取轮询继续工作。

保留窗口判断使用项目 cursor 索引和固定有界扫描，不在每次订阅请求中执行全历史计数。活动表是审计通知，不替代任何业务事实表。

## 3. 指标口径

默认窗口为近 168 小时，可读取 1～2160 小时：

- Attempt：总数、终态数、成功、失败、LOST、ABORTED、当前活动数；
- 健康：当前 Attempt 的 UNKNOWN 和 LOST 数量；
- 性能：有开始/完成时间的 Attempt P50 与 P95 执行时延；
- 错误率：`(FAILED + LOST + ABORTED) / terminal`；
- Token：Brain Run 的 input、output 和 total Token；
- 活动：窗口事件数、最新游标、保留窗口下界和最近事件延迟。

Planner 当前没有独立 Token 持久化字段，因此 Token 指标只统计已审计的 Brain Run，不推断或伪造 Planner Token。
