# 知枢阶段 10.1A：并行调度提案与 Workspace Lease 安全基线说明 v1.0

> 当前状态：阶段 10.1A `COMPLETED`。  
> 阶段 10 总状态：`IN_PROGRESS`。

## 1. 批次边界

10.1A 只建立 Parallel Schedule Proposal 与逻辑 Workspace Lease 的安全合同，不执行并行任务。

允许：

- 从一个当前 Plan 中选择恰好两个 `READY` 且可执行的节点；
- 校验两个节点不存在直接或传递依赖；
- 校验显式文件 scope 不重叠；
- 为每个节点确定性选择满足能力要求的已启用 Agent Profile；
- 为两个 worker 分配不同的逻辑 `ISOLATED_WORKTREE` Lease；
- 用户确认或拒绝 Proposal，并保留不可变审计事件。

不允许：

- 创建 Work Order、Task 或 Attempt；
- 启动 Agent 或 Runtime；
- 执行 Git 命令、创建分支或物理 Worktree；
- 自动合并或启动 Integration Agent；
- 修改 Legacy `AgentTaskCenter`。

## 2. 安全不变量

创建 Proposal 前必须同时满足：

1. `baseStateRevision` 和 `basePlanVersion` 等于当前权威版本；
2. 节点数量严格为两个，且 node key 不同；
3. 两个节点均为当前 Plan Version 中的可执行 `READY` 节点；
4. 两节点之间没有直接或传递依赖；
5. 每个节点都有非空、非根级的显式文件 scope，且 scope 不相交；
6. 每个节点都能匹配一个已启用且覆盖全部 required capabilities 的 Profile；
7. 同一 Plan Node 不能同时属于另一个活动 Parallel Schedule；
8. 两个逻辑 Workspace Lease 的引用必须不同。

确认时会再次锁定 Proposal 所属的 `projectId + planId + scheduleId`，并校验 State Revision 和 Plan Version 未变化。跨 Plan 路径不能确认、拒绝或重放另一个 Plan 的决策。

## 3. 状态与持久化

V18 新增：

- `parallel_schedule_proposal`：Proposal、版本基线和用户决策；
- `parallel_schedule_assignment`：两个 worker slot、节点、Profile 和 scope 快照；
- `workspace_lease`：未来物理 Worktree 的逻辑预留；
- `parallel_schedule_event`：不可更新、不可删除的审计事件。

状态流：

```text
PENDING_APPROVAL
  -> APPROVED  -> assignments READY_FOR_PROVISIONING, leases RESERVED
  -> REJECTED  -> assignments CANCELLED, leases RELEASED
  -> STALE     -> assignments CANCELLED, leases RELEASED
```

`READY_FOR_PROVISIONING` 不是已创建 Worktree，也不是允许执行 Agent。物理 provisioning 属于后续独立批次。

## 4. API

浏览器同源 Gateway：

```text
GET  /api/task-center/projects/:projectId/plans/:planId/parallel-schedules
POST /api/task-center/projects/:projectId/plans/:planId/parallel-schedules
POST /api/task-center/projects/:projectId/plans/:planId/parallel-schedules/:scheduleId/confirm
POST /api/task-center/projects/:projectId/plans/:planId/parallel-schedules/:scheduleId/reject
```

Gateway 每次先把本地项目解析到稳定 Control Project；写命令必须携带认证用户生成的 actor。Project Control OpenAPI 版本为 `1.7.0`。

## 5. 验收条件

- 创建和幂等重放返回同一个 Proposal；
- scope 冲突、依赖冲突、版本 stale、能力不满足和活动节点冲突均被拒绝；
- 确认/拒绝及其重放保持幂等，跨 Plan 决策被拒绝；
- 两个 Assignment 使用不同的逻辑 Lease；
- 确认后 Work Order 数量仍为零，Plan Node 仍为 `READY`；
- Gateway 认证、输入校验、稳定项目解析、actor 和 body 转发测试通过；
- PostgreSQL 空库迁移 V1～V18、完整测试、双端构建和 3001 实际调用通过。
