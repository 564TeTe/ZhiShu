# 知枢阶段 1：项目变化订阅设计 v1.0

> 文档性质：阶段 1.2 只读驾驶台的订阅边界与后续实现依据。  
> 状态：设计已固化；阶段 8.3 已按本文边界实现耐久游标增量拉取这一等价订阅。  
> 适用范围：新 Task Center；不适用于旧 `AgentTaskCenter`。  
> 权威事实：Spring Control Plane 的 Task / Attempt / Approval / Artifact / Follow-up / Acceptance 投影，以及 Node Runtime 事件投递健康。

---

## 1. 当前实现

阶段 1 使用确定性的轮询读取：

- 项目驾驶台每 15 秒请求一次 `GET /api/task-center/projects/:projectId/dashboard`；
- 用户选中 Task 后，详情每 15 秒请求一次 `GET /api/task-center/projects/:projectId/tasks/:taskId`；
- 服务端响应携带 `fetchedAt` 和 `staleAfterMs = 30000`；
- 前端超过 stale 窗口后明确提示数据可能不是最新；
- 单次刷新失败时保留上一次成功快照并显示失败提示；
- Control Plane 不可用、项目未登记、核心 Task 数据不可用与部分详情源失败分别展示；
- Runtime 健康只表达事件投递链路状态，不推断某个进程内 Run 是否仍存活。

轮询是阶段 1 的正式可信读取方式，不是伪装的实时订阅。它的优势是只依赖已经存在的稳定读接口，断线恢复等价于再次读取完整快照。

## 2. 为什么不能把单 Task SSE 当作项目变化流

现有 `GET /api/v1/tasks/{taskId}/events` 只服务于一个已知 Task：

1. `Last-Event-ID` 的顺序只在该 Task 事件流内有意义，不是项目级游标。
2. 浏览器必须事先知道全部 Task ID；新 Task 的出现无法由既有 Task 流发现。
3. 多个 Task SSE 合并后没有权威的跨 Task 顺序。
4. Approval、Acceptance、Follow-up、审批策略和项目登记变化不一定都能由 Runtime Task Event 完整表达。
5. 大量并发 Task 会产生无界连接和重连负担。
6. 原始 Runtime Event payload 不是稳定的项目驾驶台 DTO，不能直接成为前端事实模型。

因此，新中心不得通过同时连接多个单 Task SSE，再在浏览器中拼接的方式宣称已经具备项目级变化订阅。

## 3. 未来项目级变化接口

建议由 Spring Control Plane 保存项目级耐久变化记录，Node Gateway 只承担用户认证、Service Credential、连接转发和错误翻译：

```text
Browser
  → GET /api/task-center/projects/:projectId/changes
  → Authenticated Node Task Center Gateway
  → Spring Project Change Stream
  → PostgreSQL durable project cursor
```

概念事件信封：

```json
{
  "schemaVersion": "1.0",
  "eventId": "uuid",
  "projectId": "uuid",
  "cursor": 1842,
  "occurredAt": "2026-08-15T00:00:00Z",
  "changeType": "TASK_UPDATED",
  "resourceType": "TASK",
  "resourceId": "uuid",
  "taskId": "uuid",
  "attemptId": "uuid",
  "sourceEventId": "uuid"
}
```

约束：

- `cursor` 必须由项目级耐久存储单调分配，不能复用某个 Runtime Run 的 `sequenceNo`；
- `eventId` 用于端到端去重，`sourceEventId` 可关联已有 Runtime Event；
- 事件只通知“哪些事实可能变化”，前端仍通过权威读接口取得展示模型；
- payload 不复制完整 Artifact 内容、模型输出或不稳定的原始 Runtime payload；
- 新的长期 Project Identity 落地后，项目游标绑定稳定 Project ID，而不是绑定工作区路径；
- 协议必须版本化，不兼容字段或语义变化需要升版。

首批 `changeType` 建议覆盖：

- `TASK_CREATED` / `TASK_UPDATED`；
- `ATTEMPT_CREATED` / `ATTEMPT_UPDATED`；
- `APPROVAL_UPDATED`；
- `ARTIFACT_PUBLISHED`；
- `FOLLOW_UP_CREATED`；
- `ACCEPTANCE_RECORDED`；
- `APPROVAL_POLICY_UPDATED`；
- `PROJECT_SNAPSHOT_INVALIDATED`，用于无法安全细分时要求全量刷新。

## 4. 游标、重连与缺口恢复

建议使用 SSE，并允许以下两种等价恢复输入：

- 标准 `Last-Event-ID: <cursor>`；
- 首次连接或调试场景使用 `?after=<cursor>`。

服务端语义：

1. 首次无游标连接只发送连接后的变化，并先要求客户端读取一次完整 Dashboard 快照。
2. 带游标重连时重放 `cursor > lastCursor` 的事件。
3. 投递保证为 at-least-once；允许重复，不允许静默跳过仍在保留窗口内的事件。
4. 如果游标过旧、未知或保留窗口已截断，返回明确的 `CURSOR_EXPIRED` / `RESYNC_REQUIRED`，客户端必须全量刷新。
5. Heartbeat 只维持连接，不占用项目业务游标，也不改变项目状态 revision。
6. 同一连接内按 cursor 递增；迟到的源 Runtime Event 在写入项目变化记录时获得新的项目 cursor。

前端恢复流程：

```text
读取 Dashboard 全量快照
  → 记录 snapshotWatermark / 当前 cursor
  → 建立项目变化 SSE
  → 按 eventId 去重并推进 lastCursor
  → 失联后携带 lastCursor 重连
  → 游标过期时重新读取完整快照
```

## 5. 前端幂等与查询失效

项目变化事件不直接修改复杂的 Dashboard 对象，第一版只驱动查询失效：

- Task / Attempt / Acceptance 变化：刷新 Dashboard；若为当前选中 Task，同时刷新详情。
- Approval / Artifact / Follow-up 变化：刷新对应 Task 详情，并刷新 Dashboard 的注意事项摘要。
- Approval Policy 变化：刷新 Dashboard。
- 未知版本、未知类型或 `PROJECT_SNAPSHOT_INVALIDATED`：执行完整刷新。

客户端保存有限大小的 `eventId` 去重集合，并且只在成功处理事件后推进 `lastCursor`。重复事件只会重复触发幂等 GET；不能触发创建、审批、取消、重试、验收或 Follow-up 等写操作。

## 6. 认证与资源边界

- 浏览器继续只持有现有 User JWT，不能获得 Control Plane 或 Runtime Service Token。
- Node Gateway 必须用本地 Project 解析既有 Control Project，并在订阅前验证项目归属。
- Spring 只允许订阅 actor 有权查看的 Project；阶段 2 再完善稳定 Identity 与 actor 审计。
- 项目流不得泄露其他 Project 的 Task ID、Artifact 元数据或游标活动。
- Runtime Token 只用于 Runtime 信任边界，不能冒充用户订阅或用户决策。

## 7. 实施顺序与验收

阶段 1.2 只交付本文，不新增数据库迁移、Project Change 表、SSE Route 或浏览器订阅代码。当前 15 秒轮询继续作为 G1 验收路径。

未来实现项目变化流时至少验证：

1. 新 Task 可被项目订阅发现；
2. 断线重连不漏事件，重复事件不产生副作用；
3. 多 Task 并发变化按项目 cursor 可恢复；
4. 游标过期会明确全量重同步；
5. 未认证、跨项目和错误 Service Credential 被拒绝；
6. 关闭订阅后仍可退回轮询，不影响现有执行事实；
7. 单 Task SSE 继续保持原语义，不被无版本改变。

## 8. 阶段 8.3 实现回写

阶段 8.3 采用 PostgreSQL `project_activity_event` 与项目级耐久 cursor，通过有界增量 HTTP 拉取实现等价订阅；没有聚合单 Task SSE。实现保留 at-least-once、`eventId` 去重、断线重放、`RESYNC_REQUIRED` 全量同步、项目归属校验和轮询回退语义，详细结果见 `知枢_阶段8.3_项目订阅断线恢复与运行指标说明_v1.0.md`。
