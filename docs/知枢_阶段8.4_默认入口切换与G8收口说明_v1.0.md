## 1. 默认入口语义

- `VITE_ZHISHU_TASK_CENTER_ENABLED` 默认启用，控制新中心 Tab 是否可见。
- `VITE_ZHISHU_TASK_CENTER_PRIMARY` 默认启用，控制一次性默认页签迁移。
- 首次 rollout 时，未保存页签或旧 `chat` 页签迁移到 `task-center`。
- 已保存 `agent-tasks`、其他内置页签或插件页签时保持原选择，同时把本 rollout 标记为已处理。
- rollout 完成后尊重用户后续页签选择，不持续强制停留在新中心。
- 新中心被禁用时，持久化的 `task-center` 页签会被拒绝并回到 Chat。

一次性标记使用 `zhishu.task-center.primary-rollout=1`。后续若需要新的迁移策略，必须升级版本值，不得复用旧标记改变已处理用户的选择。

## 2. 回退矩阵

| ENABLED | PRIMARY | 启动行为 | 数据影响 |
|---|---|---|---|
| true | true | 执行一次性迁移；随后尊重持久化页签 | 无 |
| true | false | 不执行新迁移；有效持久化页签优先，否则 Chat | 无 |
| false | 任意 | 隐藏新中心并拒绝持久化 `task-center` | 无 |

`PRIMARY=false` 只停止新的默认迁移，不会隐藏新中心，也不会主动改写已经选择的有效非 Chat 页签。需要完全隐藏入口时使用 `ENABLED=false`。两个开关都只影响前端入口，不删除或迁移 Task、Attempt、Approval、Artifact、Acceptance、Follow-up、Work Order、Project State、活动日志或指标数据。

## 4. G8 两轮验收器

`npm run demo:g8` 使用固定 Demo Repository 创建两个隔离工作区，并以 Demo 用户 JWT 调用 `3001/api/task-center/**`：

- 两轮都执行 Initial State、Brain、Planner、单节点发布、幂等 Work Order、审批、系统证据、Verification、State 回流、Brain handoff、活动和指标读取；
- 第一轮直接 `PASSED`；
- 第二轮先将首个 Execution Report 验证为 `FAILED`，确认 State Revision 不前进，再为同一 Plan Node 创建新的历史 Work Order 并最终 `PASSED`；
- 最终必须存在 `SYSTEM_VERIFIED` Execution Report Fact、已完成 Plan Node、Brain Token 指标和增量活动事件；
- 验收成功后写入 `.zhishu-demo/evidence/g8-*.json` 和 `.md`。

确定性 Planner 的 `implement` 节点现在无前置依赖，具备 `READ_FILE / WRITE_FILE / TEST`，并要求测试和系统证据可追溯，因此用户可以只批准这一个节点完成 G8 单节点闭环。`scope` 和 `verify` 仍作为可选建议节点保留。

## 5. 自动化 G8 结果

经用户授权重启 schema 2 Demo 栈后，首次真实运行暴露 `PROJECT_NOT_REGISTERED`：V6 后新 Project 的 `ensure` 没有创建初始 `workspace_binding`，而 Gateway 已只通过 workspace identity 解析。修复为 Project 尚无任何 binding 时，在同一事务内创建 `legacy-unscoped` 兼容主绑定；已有绑定历史不覆盖，无需数据库迁移。

修复后 `npm run demo:g8` 在 344.4 秒内连续两轮通过：第一轮直接 PASSED；第二轮首个 Work Order 被验收为 FAILED/REJECTED，State Revision 不推进，再创建新 Work Order 并 PASSED。最终两轮 Work Order 均为 VERIFIED，Brain handoff SUCCEEDED，Plan Node 完成，并形成 SYSTEM_VERIFIED Fact、Brain Token 和活动证据。

3001 前端收口硬化补齐了普通本地项目登记入口：未登记项目只显示一个统一登记面板，不再由 State、Brain、Plan 和指标子面板重复渲染 `PROJECT_NOT_REGISTERED`；登记后继续确认当前机器与 local project 的 Workspace Binding。Gateway 登记与路由认证定向测试、TypeScript 类型检查、ESLint 和客户端/服务端构建均通过。用户随后明确要求阶段 8 收口并进入阶段 9，本说明据此记录最终 Gate 结论。
