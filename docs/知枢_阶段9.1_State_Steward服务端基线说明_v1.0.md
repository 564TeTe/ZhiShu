# 知枢阶段 9.1：State Steward 服务端基线说明 v1.0

> 当前状态：阶段 9.1 `COMPLETED`；阶段 9 `IN_PROGRESS`。  
> 下一批：阶段 9.2 Structured Execution Report 生产适配与前端候选审阅。

## 1. Role Contract

`state-steward:v1` 只读取 StructuredExecutionReportV1 和当前 Project State，输出 `STATE_CHANGE` Proposal。权限固定为：

- 可读结构化报告与 Project State；
- 可生成 State Change Proposal；
- 不可写 State、Fact、Decision 或 Plan；
- 不可访问 Shell、Git 或工作区文件。

Steward 候选类型仅限 `DISCOVERY / DECISION / CONSTRAINT / RISK`。`FACT` 不属于候选合同；System Verified Fact 继续只由 Verification Gate reducer 生成。

## 2. 候选分类

候选按 `entryType + 标准化 title + 标准化 content` 合并，证据引用去重：

| 分类 | 条件 | 确认行为 |
|---|---|---|
| `NEW` | 当前 ACTIVE State 中无同类型同标题项 | 用户确认后写入 `USER_CONFIRMED` Entry |
| `STALE` | 当前 ACTIVE State 已有完全相同项 | 不写 State，只保留 Proposal 审计 |
| `CONFLICT` | 当前 ACTIVE State 有同类型同标题但内容不同项 | 不自动覆盖，只保留冲突供后续处理 |

确认 Proposal 只应用 `NEW`；没有 `NEW` 时 Proposal 仍可审计完成，但 State Revision 不增加。

## 3. 幂等与拒绝

- V17 唯一索引保证一个 Project 的同一 Execution Report 只能对应一个 State Change Proposal。
- 同一报告重放返回原 Proposal；即使原 Proposal 已拒绝，也不会重新生成无差别候选。
- 确认和拒绝都使用 `clientRequestId` 与认证 actor 记录 Project Change。
- 拒绝写入原因和 actor，但 `beforeRevision == afterRevision`。
- Proposal 的 `baseStateRevision` 变化时沿用现有 stale 并发保护。

## 4. API 边界

浏览器只调用受用户 JWT 保护的同源 Gateway：

```text
POST /api/task-center/projects/:projectId/state/steward/proposals
POST /api/task-center/projects/:projectId/state/proposals/:proposalId/confirm
POST /api/task-center/projects/:projectId/state/proposals/:proposalId/reject
```

Gateway 重新解析稳定 Control Project，并把 `user:<id>` actor 转发到受独立 Service Credential 保护的 Project Control `1.5.0` 内部接口。
